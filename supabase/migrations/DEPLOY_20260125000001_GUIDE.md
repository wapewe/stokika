## Troubleshooting

### Issue: Migration fails with "duplicate ID numbers" error

**Cause:** Existing data contains duplicate ID numbers

**Solution:**
1. Identify duplicates:
   ```sql
   SELECT id_number, COUNT(*) as count
   FROM field_agents
   WHERE id_number IS NOT NULL
   GROUP BY id_number
   HAVING COUNT(*) > 1;
   ```

2. Resolve duplicates (choose appropriate action):
   - Remove duplicate records if they're test data
   - Update duplicate IDs to unique values
   - Consolidate duplicate records

3. Re-run migration

### Issue: Constraint already exists

**Cause:** Migration was partially applied or run twice

**Solution:**
- This is safe! The migration uses `IF NOT EXISTS` checks
- Review output to confirm all steps completed
- If needed, run verification script to check status

### Issue: Index creation fails

**Cause:** Index with same name might already exist

**Solution:**
```sql
-- Check existing indexes
SELECT indexname FROM pg_indexes 
WHERE tablename IN ('field_agents', 'supervisors');

-- Drop conflicting index if needed
DROP INDEX IF EXISTS [index_name];

-- Re-run migration
```
